# OpenBioSingleCellPathwayScoreTTest — official usage research

## P0 finding

The current node joins per-cell pathway scores to cell metadata and applies `scipy.stats.ttest_ind` to cells in two
Conditions. Cells from the same Sample are correlated subsamples, not biological replicates. The reported p-values
therefore exhibit pseudoreplication and can become arbitrarily small as more cells are sequenced. The current
operation is not a valid Condition contrast and must not remain executable.

The current code also uses the equal-variance default, silently omits non-numeric/NaN scores, does not require a
Sample column or minimum replicate count, reports no effect uncertainty or degrees of freedom, and applies BH only
to whichever finite rows happen to survive.

## Reviewed replacement method

The base environment currently provides SciPy 1.17.1. Its official public interface is:

```python
result = scipy.stats.ttest_ind(
    sample_means_a,
    sample_means_b,
    equal_var=False,
    nan_policy="raise",
    alternative="two-sided",
)
interval = result.confidence_interval(confidence_level=0.95)
```

- Official API: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ttest_ind.html
- FDR API: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html

`equal_var=False` is Welch's independent-samples t-test and returns statistic, two-sided p-value, Welch-Satterthwaite
degrees of freedom, and a confidence interval for mean A minus mean B. It is appropriate only after one independent
value has been constructed per Sample. The reviewed construction is the arithmetic mean of finite cell-level scores
within one selected population and one Sample, with a declared minimum number of cells. The test then compares those
Sample means across two Conditions.

Every Sample must map to exactly one Condition. Samples below the population-cell threshold are excluded before the
test and fully disclosed. Welch variance is computationally defined from two retained Samples per Condition, so two
is the hard minimum; three or more remains the recommended reporting default, and an arm with only two is prominently
flagged as fragile. All score columns in the declared score artifact form one multiple-testing family, including
non-significant results. BH is applied once across that complete family.

Technical batch is a nuisance variable, not a synonym for Condition or Sample. A two-sample t-test cannot adjust it.
An optional Technical batch field is used only for audit. A Sample spanning batches, partial imbalance, or perfect
Condition/batch confounding does not make the arithmetic fail, but it makes the unadjusted formal Condition
interpretation invalid; the summary must record that status and the exact mappings. Designs needing covariate
adjustment must use a Sample-level regression module instead.

## Scientific reporting practice

For each pathway disclose retained/excluded Sample counts, cells contributing to each Sample mean, group means and
SDs, mean difference (A minus B), 95% CI, Welch statistic/df, raw p, complete-family BH p, and direction. Do not
interpret a non-significant result as equivalence or a positive score as causal activity. Scores generated by AUCell,
GSVA, and Scanpy panels are not interchangeable; upstream method/resource/expression-state provenance must be bound
to the contrast.

## Report/code implications

The summary must state Sample as inference unit, aggregation rule, selected population, Condition contrast, replicate
and cell-support counts, complete pathway family, key effects/uncertainty, exclusions, Technical batch audit,
limitations, references, and exact software versions. Generated code must perform the same aggregation/preflights,
return `(result_dataframe, summary_dict)`, and never fall back to a cell-level test.
